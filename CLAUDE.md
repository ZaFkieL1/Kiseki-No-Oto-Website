# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Note: `AGENTS.md` holds the same content for other agent tools. The Astro scaffold hardlinked the two files, but ordinary edits break the link — after changing this file, copy it over `AGENTS.md`.

## Commands

Package manager is **pnpm** (`pnpm-lock.yaml`); Node >= 22.12.0.

| Command | Action |
| :-- | :-- |
| `pnpm install` | Install dependencies |
| `pnpm build` | Production build to `./dist/` |
| `pnpm preview` | Serve the built site locally |
| `pnpm check` | Type-check everything (`astro check`) |
| `pnpm icons` | Regenerate every icon and the share card from the lockup |
| `pnpm generate-types` | Rewrite `worker-configuration.d.ts` from `wrangler.jsonc` |
| `npx wrangler deploy` | Ship it (after `pnpm build`) |
| `pnpm test` | Run the unit tests once |
| `pnpm test:watch` | Run them in watch mode |
| `pnpm astro ...` | Astro CLI (`astro add`, ...) |

`pnpm build` still only strips types — **`pnpm check` is the only thing that type-checks**, so run it before believing a change is done. TypeScript is pinned to **6.x on purpose**: `astro check` needs a programmatic API that TypeScript 7's native compiler does not expose yet, and bumping the major silently breaks the command.

Vitest covers pure logic only — the store, its validation, and derived values. There are deliberately no component tests: canvas, `useSyncExternalStore` and `AudioContext` make them expensive and fragile, and they are most of this code. Do not write type-only tests either — `import type` is erased before the test runs, so the suite passes whether or not the type exists; that is what `pnpm check` is for. There is still no linter or formatter; don't invent one.

astro dev --background

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`. Dev server defaults to `localhost:4321`.

## What this is

KISEKI NO OTO (奇跡ノ音) — the site for **a Colombian net-label putting out J-Core and Jaycore**, built as **LABEL_OS**: a boot sequence that hands off into an operating-system-style interface.

The narrative order is deliberate and worth preserving: **boot → identity → transmission → catalogue.** `01 SYSTEM` is the label's identity page, not the player. The nav label and the content have to agree; a view called SYSTEM that led with "NOW PLAYING" is exactly the confusion this structure fixed. The dock plays underneath all of it, which is what lets SYSTEM be about the label rather than about a track.

In the hero, identity and transmission run **side by side rather than one scroll apart** (`IdentityHero` + `SignalPanel`): the lockup and the statement on the left, the loaded record hung off a full-height rule on the right. The left column still speaks first — the record is a column, not the headline. That rule is doing real work: the hero used to be a stack in the left third with two thirds of unlit screen beside it, and the rule is what turns the remaining black into framed space instead of leftover space. Do not fill it further.

**`src/lib/data.ts` is the seed, not the source.** The live catalogue is **Firestore**, behind the same `subscribe`/`getSnapshot` singleton in `src/lib/store/`, read through `useCatalogue()`. Collections are `releases` (doc id = `cat`), `artists` (id = `key`), `events` (id = `id`), plus two `meta` documents: `featured` and `socials`.

- **The store opens on the seed and swaps once.** `deck` is built at module scope and needs a record before the first render, so `getSnapshot()` answers with `data.ts` until Firestore reports. `Snapshot.origin` says which you are looking at. The swap waits for **all five** listeners — emitting per response would paint cloud releases beside seeded artists for a frame.
- **There is no seed-publishing button.** `data.ts` is a first-paint fallback and nothing more — the real catalogue is typed into KERNEL. A control that overwrites every record with fiction is not one to leave lying around next to a live catalogue.
- **`store/rules.ts` holds the catalogue's own rules** — dependency guards, the featured check, the sorting — apart from any backend, because the localStorage adapter and the Firestore one had begun restating them at each other.
- `ignoreUndefinedProperties` is on. Optional fields are `undefined` all over the catalogue and Firestore rejects those by default.

**Events are online.** `LabelEvent` has a `platform` and a `stream` where a venue and a city used to be, a `flyer` (the invitation image), a `timezone` label and a `schedule` of slots. There is **no stored `state`**: it is derived from the date in `catalogue.ts`, because a hand-set status goes stale. Times are displayed exactly as captured and never converted — the flyer is the source. Slot artists are free text with an optional `artistKey` link, so guests from outside cannot inflate `roster`.

**Nothing in the seed is invented any more.** It held twenty fictional records, twelve acts and six events so an empty site had something to draw; all of it is gone, leaving `KSK-038` and `kernbrecher`, which are real. **Do not seed fiction again** — this file is what the site shows before Firestore answers and what the `<noscript>` listing ships, so an invented record is a release announced that does not exist, and the deck will eventually play it. Add through KERNEL. `REAL_RELEASES` must stay non-empty, though: `featuredTrack()` reads `releases[0]` at module scope, before the cloud has said anything.

**SEO lives entirely in the head and the `<noscript>` listing.** A crawler runs no JavaScript worth counting on, so the interface is invisible to it — `index.astro` carries the title, description, canonical, Open Graph, Twitter card and a `MusicGroup` JSON-LD block, every line of it read out of `label` so it cannot drift from the site. `robots.txt` and `sitemap.xml` are static files in `public/`, and **neither names the console**: a robots file is public, so a `Disallow` for a secret path is how you publish it. `sameAs` is absent from the JSON-LD on purpose — the social links live in Firestore and this page is built long before anyone can read them.

**Icons are generated, not drawn.** `pnpm icons` runs `scripts/icons.mjs`, which builds the favicon (a hand-written ICO holding PNGs at 16/32/48 — sharp has no ICO encoder), the apple-touch icon, the manifest icons and the 1200×630 share card from `public/KNO blanco.png`. **`flatten` is the whole trick**: the lockup is *white ink on real transparency* — `blanco` is the ink, not the ground — so anything compositing it on white gets an empty frame, which is exactly what social scrapers do. Everything is flattened onto `--void` first. There is deliberately **no `favicon.svg`**: the scaffold shipped one, browsers prefer it over the `.ico`, and it was Astro's rocket — the site was serving somebody else's logo in the tab.

**The logo has no ground of its own.** `public/KNO blanco.png` is a *white* brush lockup on real transparency — measured, not assumed: alpha runs the full 0–255 and the RGB channels carry white ink. It is composited with `mix-blend-mode: screen` over an isolated `var(--void)` background, which keeps the glow of the brush against the page. Anywhere it is *not* over dark — a browser tab, a social card — it has to be flattened onto black first, which is what `scripts/icons.mjs` does. It is served as `public/logo-kno.webp` (900px, 160KB) because the source PNG is 1.4MB, which is far too heavy for a hero image; regenerate with sharp if the artwork changes. The lockup already contains the name (a KNO monogram over "Kiseki No Oto" in small caps), so it *replaces* the typographic wordmark in SYSTEM rather than sitting beside it — the kana under it is the other half of the name, not a repeat. It is the artwork of that screen, not a header: everything under it is deliberately set small so the brush keeps the weight, and the statement is the only other thing allowed to be loud. Its width is `min(100%, 48vh, 44rem)` — width-driven because the `1024/720` crop only tolerates being cut top and bottom, with the `vh` term there to stop it pushing the statement off a short window.

Identity copy lives in the `label` export in `data.ts` — name, kana, genres, tagline, etymology, manifest — so SYSTEM reads as a record being displayed rather than prose baked into a component. **Focus is derived from `genres`, not typed** — it was a second copy of the same list, so adding a genre left Focus saying what it said last month; `focus()` in `data.ts` joins them, and the meta description and the JSON-LD `genre` read the same array. Counts (catalogue size, roster size, which record is loaded) are derived — the roster figure through `roster()`, so it counts the same acts the artist database lists — and cannot drift; they are read out at the foot of the hero's signal column and deliberately **not repeated** in the manifest below, which is editorial only. Prose fields carry both languages as `{ es, en }` and are read through `pick()`; names, glyphs and genres do not have two versions. The copy is the label's own description of itself — geek sounds, limitless energy, a vision of its own — not anything written for a demo, and `origin` is `COLOMBIA` because that is now known. There is still **no founding year**: that number is not known, so it is not shown.

## Architecture

One page, one island. `src/pages/index.astro` mounts `<LabelOS client:load />` and does nothing else but the document head and a `<noscript>` catalogue listing. **That listing is built from the seed, not the store** — the page renders at build time and cannot read `localStorage`, so it shows the shipped catalogue rather than live edits, and still will under Firestore while the pages prerender. Accepted, not a bug. **Both pages are still prerendered under the Cloudflare adapter** — the only thing rendered on demand is the upload route.

Anything that interpolates a catalogue count must be built **inside** a component, not at module scope. `LabelOS`'s `VIEWS` array and `BootSequence`'s `SCRIPT` both do this (`buildViews`, `buildScript` + `useMemo`); as module constants their numbers would freeze at whatever the build shipped. There is no routing — `LabelOS.tsx` holds a `ViewKey` in state and swaps panes in place behind an "ACCESSING …" transition. Adding a destination means adding an entry to the `VIEWS` array; its index is its keyboard shortcut. **There are four:** SYSTEM, RELEASES, ARTISTS, EVENTS. `ArchiveView.tsx` and `ShopView.tsx` are still on disk but nothing imports them, so neither is bundled — the archive restated the catalogue the scenes already are, and the shop had nothing to sell. `ShopItem`/`shop` in `data.ts` are the same story. Delete them or wire them back; do not leave a third state where a nav entry exists and the view does not.

Things that are load-bearing and not obvious from one file:

- **`src/lib/audio.ts` owns playback, not React.** `deck` is a module singleton with its own subscribe/getSnapshot pair; components read it through `useDeck()` (`useSyncExternalStore`). It must stay outside React state — the transport lives in the dock and has to survive every view change. `deck.position` is read directly per frame by anything drawing; only the clock re-renders, at 10Hz, via `usePosition()`.

- **One playback path: uploaded files, and nothing else.** A release with a `file` on the track streams through `MediaElementAudioSourceNode`; a song without one **does not play at all** — `play()` answers `NO SIGNAL` with "no file has been uploaded", and `next`/`prev` walk `playable()`, a flat list of only the songs that have a file. There used to be a second path: a synthesised J-Core signal for records with no audio, which existed because the catalogue was invented and there was nothing real to play. That reads very differently once the catalogue is real — generated music coming out of a label's own record sounds like theirs and is not. **The sequencer is still in `audio.ts` and is unreachable from the transport**; silencing it and deleting it are separate decisions. Telemetry reports `STREAM` or `NONE`, never `SYNTH`. The deck boots with whatever song carries the `featured` mark, falling back to the newest record's first playable track.

- **A release has a `Track[]`, not a track count**, and **no artist of its own**. The label publishes the record; the songs carry the credits, which is what lets a compilation hold four acts without any of them owning the release and without a fake "V.A." roster member. `releaseCredit()` is the only honest way to ask who is on a record: one name when the songs agree, `V.A.` when they do not, the label's own name while the running order is empty. `releasesByArtist` searches tracks, and so does the delete guard in `store/rules.ts`.
- **The sleeve belongs to the release**, so a twelve-track album is one upload, not twelve. `featured` is `{ cat, track }` — a record *and* a song. `deck.load(release, track)` takes both, `next`/`prev` walk the running order before rolling into the neighbouring record, and the dock names the artist of **the loaded song**, not of the record.

- **A song that ends is the end of it.** `ended` used to call `next()`, which is what a radio does — and what it did was start a different act's record at someone who had chosen this one. It stops at zero in `STANDBY` now. `next`/`prev` are still there, because a control being pressed is somebody asking.
- `Release.link` is where the record lives — Bandcamp, SoundCloud, anywhere. `ReleaseLink` recognises a few hosts to name the destination and otherwise says "Open the release"; with no URL it shows a visible gap rather than a dead control.

- **`toggle()` asks the transport, not the flag.** A track that ends somewhere the deck cannot carry on from leaves `playing` true with nothing behind it; the next press then reads as a *pause*, does nothing audible, and the button looks broken. `running` checks the element or the timer, which is the question actually being asked.

- **The transport reports four phases, and one of them is a failure.** `STANDBY · FETCHING · TRANSMITTING · NO SIGNAL`, read out in the hero. `FETCHING` is not decoration — a file coming off the bucket takes real time, and a control that shows nothing for two seconds gets pressed again. `NO SIGNAL` exists because **the media element had no `error` listener at all**, so a 404 or an undecodable file produced silence and no explanation. `problem` carries the reason to the readout's tooltip, and a song with no file uploaded says so there. `intent` is what keeps a file failing on mount — `prime()` attaches before anyone asks for sound — from putting `NO SIGNAL` across the hero unprompted.

- **The deck follows the on-air mark until someone touches it.** `deck` is built at module scope, so its `featuredTrack()` runs before Firestore has said a word and reads the *seed* — which is why marking a song on air in KERNEL used to change nothing on the site. It subscribes to the store now and adopts the marked song whenever the mark or the catalogue moves — and **the comparison includes the track's source, not just `cat` and `track`**: with only the identifiers, a cloud record carrying the same catalogue number looked unchanged, so the deck held the *seeded* version of it and played a file from before the upload existed. It adopts **only while `touched` is false**: `play()` and `load()` set it, and after that the deck belongs to whoever is listening. Yanking a record out from under someone is worse than showing them a mark one edit old.

- **`preview` is a detour, not a mode.** `deck.loadPreview(release)` runs `release.preview` with the loaded track still pointing at a real index, because the dock needs something to name — and `attachMedia` picks the file off the flag. Any `load()` clears it. A preview that ends stops rather than rolling into track two, because it is a sample of a record, not a position in a running order.

- **`deck.duration` is authoritative, never `release.duration`.** For a real file the length comes off the element's `loadedmetadata`; the number in `data.ts` is a placeholder (`0` = unknown) and using it to map a seek position would land in the wrong part of the track. `deck.prime()` attaches the element on mount — without an AudioContext — so the duration and waveform are ready before the first play. Seeks issued before metadata arrives are held in `pendingSeek` and applied on arrival.

- **The scrubber is static by design.** `src/lib/peaks.ts` decodes the file once via `OfflineAudioContext` (at 11025Hz, to keep peak memory down) and measures a real peak envelope; the bars are the track's own dynamics and do not animate. Only the progress fill and playhead move. Do not reintroduce analyser modulation here — it makes the strip hard to aim at and shows nothing true. Analyser reactivity belongs to the artwork and the ambient field.

- **Audio-reactive motion goes through CSS custom properties, not renders.** `useLevelBus()` runs a single animation frame loop that writes `--lvl-bass` / `--lvl-mid` / `--lvl-high` onto `documentElement`. Anything that should move with the music reads those in the stylesheet. Do not add per-frame React state for this.

- **The accent colour is per-release.** Each release carries a `hue`; `LabelOS` writes it to `--hue` and the whole chassis retints. Canvas and CSS both use `hsl()` so they can be handed the identical colour — don't reintroduce OKLCH for the accent without changing both sides.

- **Sleeves are real when they exist, generated otherwise.** Setting `cover` on a release uses the image everywhere (disc bay, dock, hover bleed) and its dominant hue is sampled to drive `--hue`, so the accent comes from the actual artwork. Without one, `src/lib/artwork.ts` draws a sleeve deterministically from `release.seed` — same catalogue number, same cover, always. Generated sleeves are cached only once `document.fonts.status === "loaded"`, or the Japanese glyph bakes in at a fallback face; components take `useFontsReady()` as an effect dependency to redraw.

- **Every colour outside the accent has exactly one job**, and the palette says so in `global.css`: `--ice` is system status, `--amber` is depleted/archived, `--live` is green and means one thing only — a file is in the bucket, in KERNEL. Reusing one of these for decoration is how a palette stops meaning anything.

- **The site is Spanish, with English as the second door.** The label is Colombian, so `es` is the default and what the `<noscript>` listing ships; `en` is a switch in the bar, not a flag menu, because there are exactly two. `lib/i18n.ts` is a fourth `subscribe`/`getSnapshot` singleton alongside `deck`, `store` and `session`: `useLang()` subscribes, `t()` reads, `pick()` takes the current half of a `{ es, en }` pair in `data.ts`. **The dictionary is typed against the Spanish column**, so a key added to one language and forgotten in the other will not compile. Note the whole tree repaints off the single `useLang()` in `LabelOS` — nothing below it is memoised, and wrapping a view in `React.memo` would freeze its words mid-switch.

- **KERNEL is English only.** It is a console for the people who run the label, not a page for readers, and translating it would double the surface for no reader's benefit.

- **Typography encodes who is speaking.** `Martian Mono` is the machine — boot log, telemetry, catalogue numbers, formats, dates. `Zen Kaku Gothic New` is the humans — artist names, release titles, event names. Machine-generated and human-authored content never share a face. Keep this rule when adding UI.

- **The chassis does not scroll.** `body` is `overflow: hidden`; `.os` is a `100dvh` grid of bar / body / dock, and `.pane` scrolls internally. A `transform` on `.pane` would make it a containing block and break anything positioned `fixed` inside a view (the release scroll indicator) — that is why `pane-in` animates opacity only. A view can add a class to the pane via `paneClass` in the `VIEWS` array; `pane--scenes` is what gives the catalogue its scroll snapping.

- **Releases are scenes, not rows.** `components/releases/` renders one viewport-sized environment per record, alternating side to side. `ReleaseBackground` falls back in two tiers — the square `cover` blown up and blurred, else a hue gradient. There used to be a third for a dedicated wide `desktopArtwork`; that field is gone, because one uploaded sleeve per record is the whole artwork story now and a second art slot was a field nobody was going to fill. `ReleaseDatabase` runs two IntersectionObservers against the pane: one decides which scenes get their artwork mounted (`near`), the other decides which record the interface is currently about. **Artwork must stay gated on `near`** — a full catalogue of live canvases would cost hundreds of megabytes, which is also why `artwork.ts` keeps a capped LRU.

- **Bandcamp is the destination, this site is the curation.** The scene answers what/who/where and hands off. A release with no `bandcamp` URL shows a visible gap rather than a dead link.

- **The scene leads with the record's own name, and the running order carries the credits.** `ReleaseInfo` used to headline `releaseCredit()`, so a compilation announced itself as `V.A.` — the one credit that names nobody — with the title in the small face underneath. The title leads now; the credit line under it is drawn **only when one act holds the whole record**, because on a compilation the list names the acts row by row and repeating one name down five rows is noise. The id line prints the whole catalogue number (`KSK-038`), not `RELEASE_038` — the number is what the record is filed under, and half of it was being thrown away. The list stands **five rows open and scrolls for the rest**: the row height is fixed so five is exact and the sixth row is cut at the fold, `overscroll-behavior: contain` keeps the end of the list from handing the wheel to the next scene, and the bottom fade (`rel__list--more`) is only drawn when there is actually more. **A row is a link, not transport** — it opens `track.audio` in a new tab, and it is the scene's only way into a *song*. PLAY PREVIEW sits beside the release link again, but it plays the record's `preview` — one uploaded file that is the record, not a track — and it is drawn **only when that file exists**, so it is never a play button with nothing behind it. `audio` is purely a destination — what the deck plays is `file`, and `trackSource()` is what keeps the two straight. A row whose song has no `audio` stays inert rather than becoming a control that goes nowhere, and keeps the arrow's column so the titles stay aligned. Rows are `2.5rem` under `pointer: coarse` — a 28px band is not a touch target.

## KERNEL — the console at a private address

A second Astro page with its own island (`components/admin/`), so none of the editing code reaches a visitor — the build emits `AdminOS` as a separate chunk that `index.html` never references. It is called **KERNEL**, never "admin" or "maintenance", in every piece of user-facing copy.

**The address is the filename.** It was `/admin`, which is the first path anyone tries. `src/pages/kernel-<slug>.astro` is the whole mechanism: renaming that file moves the door, and that is how the address is rotated. **The page itself is gitignored** (`src/pages/kernel-*.astro`) and `docs/kernel-page.astro.example` is the committed copy — the repository is public, and a public repository that carries the page carries the address with it. Copy the template into `src/pages/` under a name nobody guesses; it must not stay in `docs/`, because being a route is the entire point of it. Be exact about what it buys — it keeps the door **out of sight**, it does not lock it; the lock is `firestore.rules` and `EDITORS`, which refuse a stranger who finds the page and signs in. There is deliberately **no redirect from `/admin`, no robots entry, and no real `<title>`**: each of those points straight back at the address.

- **`client:only="react"`, not `client:load`.** The console reads `localStorage`; server-rendering it would paint the seed and then swap.
- **`useEditor` owns the draft, the dirty flag and the save state.** Writes are `async` because the store's are, which is why there is a saving state at all — none of it changes when Firestore lands.
- **`seed` is derived, never typed.** `hash(cat + title)`, exactly as in `data.ts` — which is why `hash` is exported. The form says out loud that editing either field redraws a generated sleeve.
- **Validation is pure and tested** (`store/validate.ts`). Slot errors are keyed `schedule.<index>.<field>` so a row can show its own message.
- **Deleting an artist with releases is refused by the store**, not just hidden in the UI — the rule lives where it cannot be bypassed.
- **Schedule rows are not sorted while you type.** The store sorts on save, so a half-typed hour never jumps out from under the cursor.
- **The release form follows the order you know things in:** identity (catalogue number, date, type, title), where it lives, then the songs, then the sleeve. Track rows keep the order you type them — nobody sorts a tracklist alphabetically — with explicit ↑/↓ to reorder, and a new row inherits the previous row's credit because most records are one act.
- **The Ko-fi ask is not a social link.** `label.support` is a URL in `data.ts`, drawn as its own control under the list rather than as a row in it: a place the label posts from and a place a reader puts money are different kinds of thing. The copyright year beside it is read from the clock — a typed one is wrong every January and nobody comes back for it.

- **Social links are data, not code.** `meta/socials` holds `{ name, url }` rows, typed into KERNEL's fourth panel, and `01 SYSTEM` reads them off the store. They replaced a `contact` block of three hardcoded fields in `data.ts` — email, Bandcamp, Instagram — where changing where the label could be found meant a code edit and a deploy. **The network name is typed, never chosen from a list**: a fixed set of networks is wrong the week the label joins a new one, and the name is the word the reader sees. With nothing on file `01 SYSTEM` draws no row at all, rather than a Contact heading with nothing under it.

- **KERNEL is responsive, and only the rail scrolls sideways.** `min-width: 0` runs down `admin.css` on every grid and flex child holding text or a control — without it a child's default `auto` minimum refuses to shrink past its content, one long email address or one seven-column track row pushes the console wider than the screen, and **the whole page** pans horizontally. Below `62rem` the rail turns into a row with `overflow-x: auto` and non-shrinking items: four sections do not fit across a phone, wrapping them costs a second row of chrome on the smallest screen there is, and shrinking them makes four tap targets nobody can hit. `overscroll-behavior-x: contain` stops the end of the rail from handing the pan to the page.

- **`SocialsPanel` does not use `useEditor`.** That hook owns *a* draft picked out of a list; this is one document, so the panel is the record. It takes the cloud's version only while nothing is being typed — the store swaps from the seed a moment after mount, and a form that ignored the swap would be editing a list it had already replaced.

- **An artist card is that act's profile link.** `Artist.link` — Bandcamp, SoundCloud, Instagram, wherever they live — and the card in `03 ARTISTS` is an `<a>` to it. Pressing a card used to load the act's newest record into the deck; that was a nice trick and the wrong answer to the gesture, because someone tapping a name on a roster page is asking who this is, not asking for a song. **An act with no link keeps the card as a card** — information, nothing to press, no hover lift — which is the same rule the release button and the stream button follow.

- **Everyone credited is filed; `guest` decides who is public.** A track cannot credit an act that does not exist, so every name on a song has a full entry — the track's artist dropdown files new ones inline (`+ New artist…`) rather than sending you to another screen. The `Guest` toggle on the artist form is what keeps a one-off feature out of `03 ARTISTS` and out of the figures that describe the roster. **The rule is `publicRoster()` in `store/rules.ts`, read through `roster()`, and that is the only place it is decided** — the artist database, the hero's Roster figure and the boot log all count through it, so the number and the list cannot disagree. (This replaces the earlier flat roster, which itself replaced a `roster`/`base` pair; the flag is back because a guest on one compilation is not one of the label's acts.)
- **`V.A.` is derived, never stored.** There is no V.A. artist to credit — `releaseCredit()` returns it when a record's songs name different acts, which is exactly what a compilation is.
- **The catalogue number says what the record is, and is never typed.** `KNO<PREFIX>-####` — `KNOLP` album, `KNOEP`, `KNOSNG` single, `KNOCOMP` compilation, `KNORMX` remixes — four digits, and **each type runs its own series**, so `KNOEP-0001` and `KNOSNG-0001` both exist. `CAT_PREFIX`, `catPattern()`, `catMatchesType()` and `nextCat()` in `store/rules.ts` are the only place the format is written: `validate.ts` builds its regex from `catPattern()` rather than spelling one out, which is the whole point — the old `KSK-###` was written by hand in `validate.ts` *and* in the KERNEL form, so what was accepted and what was minted could drift. `nextCat()` is the highest number used plus one, **not** the count plus one: deleting a record out of the middle must not hand its number to the next one. The Catalogue field is a `ReadOnlyField`, not a disabled input — a disabled control reads as one that might come back, and this is not a control. On an unsaved record it re-mints when the Type dropdown moves; on a saved one the number is **frozen**, because it is the document id and the R2 folder. Moving it is `store.renumberRelease(from, to)` behind an explicit control that only appears when `catMatchesType()` is false. That method exists rather than `saveRelease` + `removeRelease` because `removeRelease` calls `reFeature()` and would hand the on-air mark to an unrelated record instead of following this one. `Release.id` is gone: its only reader was the line that minted the next number. Records still on `KSK-###` fail validation on purpose, with a message naming the renumber control — a catalogue half in each format is the thing to avoid. Uploaded files are **not** moved; their URLs are stored values, so `/media/audio/KSK-038/…` keeps serving after the record becomes `KNOSNG-0001`.
- **`Artist.key` is never typed.** `uniqueKey()` mints it from the name on creation, numbering past collisions, and it is **frozen** from then on — it is the document id and what every track credits, so renaming an act must not move it. Problems with it are reported against the *name*, because that is the only field the reader can act on.
- **BPM belongs to the song, not the record.** An EP does not have one tempo. Nothing reads it now that the sequencer is unreachable; it is captured because it is true of the song, and it is what the visualiser would want back.
- **The cover field has no text input.** Upload or drop, nothing else — a field you can type a broken path into is a field that will hold a broken path. There is no `hue` field either: a real sleeve is sampled at runtime, so typing a number there was arguing with the artwork.
- **A song's link and a song's file are two fields, and nothing may confuse them.** `Track.audio` is the destination — Bandcamp, wherever — typed by hand and opened by a row in the release scene. `Track.file` is what we put in the bucket, and it is what the deck plays. They were one field for exactly one iteration, the upload overwrote a link that had been typed by hand, and that is the bug this shape exists to prevent. **`trackSource()` in `data.ts` is the only thing that decides what plays**: `file`, falling back to `audio` **only when it names a file** — the seeded record keeps a playable path under `public/` there, but a Bandcamp page handed to an `<audio>` element is not a slow load, it is an error the deck then repeats on every press. Returning nothing is the honest outcome: that song is not playable here, `next`/`prev` skip past it, and the readout says why rather than the transport jamming on it.
- **The cloud opens a panel, not a file picker.** A row has space for one glyph and a file has four things to say — whether there is one, what it is called, whether it plays, and how to get rid of it. So the glyph carries the state and `<dialog>` carries the answers; `<dialog>` for its behaviour only (Escape, focus held inside), styled as `.sheet` like everything else. **Green with a tick is the whole confirmation** — the row shows it without opening anything, and the panel backs it up with the file itself, named and playable.
- **An upload writes the record, not just the draft.** The bytes are in the bucket the moment the upload returns, so leaving the URL in the draft until somebody pressed Save meant a record could know nothing about a file that exists — and the green cloud went out again the next time the panel was opened. `persistUpload()` in `ReleasesPanel` saves through `useEditor.commit()`, which takes the merged value rather than the draft: `update()` is a state setter and would not have landed in the same tick. **Only for a record that already exists** — a new one has no document to update, and writing a half-typed draft would file a release under whatever catalogue number was in the box. Covers, track files and the record's preview all go through it.

- **Deleting a file deletes the object**, not just the field: `removeUpload()` sends a `DELETE` through the same door, and leaves alone any URL that did not come from an upload. Bytes nobody references are bytes nobody will ever identify later.
- **The record's preview is a field of the record, up with its information** — not a row among the songs, because it is not one. It is the only audio a visitor can start from a release scene; everything else on that screen hands off.
- **The on-air circle sets `meta/featured` and that is all it does.** What makes the marked song reach the site is on the deck's side, above. The button is only offered on a **saved** record: you cannot put on air what the catalogue does not have yet, and `assertFeaturable` refuses it in the store as well.

### Uploads — Cloudflare R2, through the site's one server route

`lib/upload.ts` sends the file, `pages/api/upload/[...key].ts` receives it and puts it in the bucket, and `ImageField` / `AudioField` are the controls. **The stored value is still just a URL**, so a record whose cover was typed in as `/cover.png` — or uploaded to Firebase Storage before the move — keeps working, and the site reads every source identically.

**Why a server route exists at all in a static site.** Firebase Storage let the browser write to the bucket directly, because its rules ran on Google's side and could read the caller's identity. R2 has no such thing: writing needs a credential, and a static page has nowhere to keep one a visitor could not also read. So this route is the only holder of write access, and it gets it as a **binding** (`env.BUCKET`) — meaning **there is no R2 access key in this repo, in the browser, or in a secret.** Nothing to leak, nothing to rotate.

- **The bucket is private, and reads come back through `pages/media/[...key].ts`.** It could have been a public `r2.dev` URL, which would cost nothing to run — but then `peaks.ts` (which fetches a track and decodes it for the real waveform) and `artwork.ts` (which reads a sleeve `crossOrigin="anonymous"` to sample the accent) would both be cross-origin reads needing a CORS policy, and both fail *silently* when it is missing. Same origin, and the question does not arise. It also keeps stored URLs **relative** (`/media/audio/KSK-038/…`), so moving the site to another domain does not strand every record saved under the old one. The cost is that a file read is a worker invocation rather than a CDN hit; at a label's traffic that is not the constraint.
- **The media route answers Range requests**, and that is not optional: the deck seeks, the browser asks for a byte range, and a route that always returns 200 with the whole file turns scrubbing into a download.
- **The site runs on Cloudflare** (`@astrojs/cloudflare`, `wrangler.jsonc`), which is what makes the binding reachable from a page route. Everything else still prerenders: the build says `prerendering static routes` for `/` and the console, and **only these two routes carry `export const prerender = false`**. A third is a decision, not a detail — the chassis is a static site with two doors, not an app server.
- This began as a standalone Worker in `worker/`. The adapter made it redundant: same origin means **no CORS policy at all**, one config, one deploy. If you find yourself re-adding a second Worker, check first whether a route here would do.
- **The route verifies the Firebase ID token itself** — signature against Google's published JWKs, then `iss`, `aud`, `exp`, `email_verified`, and the address against `EDITORS`. None of it is ceremony: skip the signature check and anyone can mint a token naming you; skip `aud` and a token from a stranger's Firebase project verifies perfectly.
- **There is almost nothing to configure.** No endpoint URL, no public base, no CORS policy, no R2 access key — both routes are same-origin and the binding is the credential. The one thing that is not in the repo is `EDITORS`, a Wrangler secret (`npx wrangler secret put EDITORS`, with `.dev.vars` covering `wrangler dev`). It moved out of `vars` when the repository went public: it is a list of people's addresses, and that is a privacy question rather than a security one — the route would work identically either way.
- **A missing binding is named, never left to throw.** Both routes check `env.BUCKET` and answer with a message; the R2 call itself is wrapped and reports what R2 said. A deployment built without `r2_buckets` otherwise answers a bare 500 to every upload and every cover on the site, which is exactly how the first production failure looked. `observability` is on in `wrangler.jsonc`, so `npx wrangler tail` streams the real thing.

- **The binding arrives as `import { env } from "cloudflare:workers"`, not `Astro.locals.runtime.env`** — that was removed in Astro v6, and the adapter throws from a *getter* if you reach for it, so optional chaining will not save you. Its types come from `worker-configuration.d.ts`, which `pnpm generate-types` writes from `wrangler.jsonc`: **rerun it after changing a binding or a var**, and note it is gitignored-shaped generated output that a fresh clone has to produce before `pnpm check` will pass.
- Keys are `covers/<cat>/<timestamp>-<name>` and `audio/<cat>/<timestamp>-<name>`, built in `upload.ts` and **rebuilt from scratch server-side** — a key is a path, and a path the caller writes is a path the caller can walk out of. Timestamped, so replacing a file never serves the old one from cache, which is what lets the objects be immutable for a year.
- **Analytics is deliberately absent.** `getAnalytics` touches `window` at import time and breaks the build.
- Firebase (now Firestore + Auth only) adds weight to the KERNEL chunk and **nothing** to the public page. Keep it that way: never import `lib/firebase.ts` or `lib/upload.ts` from a component the public island can reach.

### The door

The console is behind Google sign-in (`lib/auth.ts`, `SignInGate`) as well as behind its address. `session` is a third `subscribe`/`getSnapshot` singleton, alongside `deck` and `store`.

- **`ADMINS` in `lib/auth.ts` is not security.** It decides what the console shows, and it is read from `PUBLIC_EDITORS` in `.env` rather than typed — Astro inlines it into the browser bundle either way, so this is about not publishing a list of addresses, not about hiding one. The rules that stop a write are `firestore.rules` (the catalogue) and the `EDITORS` Wrangler secret (uploads). **Adding an editor means editing all three** — the source list only, and someone signs in to a console that lets them try writes the database then refuses. Unset, `ADMINS` is empty and authorises nobody, which is the right way for it to fail. `storage.rules` is gone with Firebase Storage.

- **`firestore.rules` is gitignored; `firestore.rules.example` is what ships.** The rules are pasted into the Firebase Console by hand, so the file in the repo is documentation — and it is the one of the three lists that has to carry the addresses literally. Copy the template, fill in `editors()`, paste it into the console.

- **The Firebase web config is in `.env`, and that did not make it a secret.** Every `PUBLIC_` variable is inlined into the bundle the browser downloads; the deployed site hands the config out to anyone who opens devtools, exactly as it did when the values were typed into `lib/firebase.ts`. What the move buys is a repository that does not trip secret scanners. What actually protects the key is on Google's side — HTTP-referrer restrictions in Cloud Console, and App Check — and neither of those lives here.
- Writes are **not** guarded client-side before dispatch. The rules refuse them and the promise rejects, which is what the save bar is for; a pre-check would only hide the error.
- `useSession` lives in `components/admin/`, **not** `lib/hooks.ts`, so `firebase/auth` never reaches the public island.
- Sign-in asks which account every time (`prompt: "select_account"`), so picking the wrong Google identity is not a one-way door.

## Keyboard

`1`–`4` switch view · `Space` play/pause · `←` / `→` seek ±5s · any key or click cuts the boot short.

**The boot runs itself through and hands off unattended** — no gate, nothing to press. It used to end on `PRESS [ENTER] TO ACCESS` so the dismissing keypress could double as the gesture the `AudioContext` needs; that is not required, because `deck.play()` builds and resumes the context on demand and the hero's PLAY is itself a user gesture. Playback still does not start on its own: PLAY is the moment the system comes alive, and nothing before it constructs an `AudioContext`.
